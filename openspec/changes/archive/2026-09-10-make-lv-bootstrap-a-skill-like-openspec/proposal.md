## Why

`lv bootstrap`'s autonomous-scan and `--paths` modes each drive a Mastra `Agent` through an LLM API call to explore the repo and draft `overview.md`/`design.md` — the scan mode alone (`generateFeatureDocsFromScan`, `src/cli/bootstrap.ts`) allows up to 30 tool-calling steps (`maxSteps: 30`), each one a separate billed round trip, purely to read files the engineer's own coding agent (e.g. Claude Code) already has open-book access to in the very session where `lv bootstrap` is invoked. OpenSpec solves the same "explore the repo, then draft an artifact" problem without any of its own LLM calls: `openspec instructions <artifact>` hands the calling coding agent a skill/command with context/rules/template, and the coding agent does the exploration and writing itself, inside its own turn, for no extra token cost. `lv bootstrap` should follow that same pattern instead of paying for a second agent to redo work the calling agent could do directly.

## What Changes

- New `lv-bootstrap` skill and, for coding agents whose command format `lv` knows, a matching slash command that perform feature-doc generation — both the "explore the repo autonomously" and "generate from given `--paths`" behaviors currently served by Mastra agents — directly within the calling coding agent's own turn, using its native file tools instead of a separate LLM call. Supported for every coding agent OpenSpec is installed for, not a fixed list — see the next bullet.
- `lv init` installs and idempotently wires this skill into every coding agent it detects OpenSpec was just installed for, the same way it already installs and patches OpenSpec's own skill/command files — detected dynamically (by finding OpenSpec's own generated skill files), not from a tool list `lv` maintains, matching OpenSpec's own `--tools` support, which likewise delegates its supported-tool list entirely to the `openspec` CLI rather than a list `lv` hardcodes. A slash command is additionally written only for the (currently two) coding agents whose command-file format `lv` has a template for — Claude Code and Cursor today; every other agent (Codex included) gets the skill only, the same way Codex already works with OpenSpec's own commands.
- **BREAKING**: `lv bootstrap <feature-id>`'s autonomous-scan mode (no flags) and its `--paths` mode — the two modes that drive a Mastra `Agent` today — are removed from the CLI. Generating or refining a feature's docs from real code now happens only through the new skill/command, run from inside a coding agent, not as a standalone terminal command. `lv bootstrap <feature-id> --new-feature` (placeholder mode, which never calls an LLM) is unchanged and stays a plain CLI command, since `lv start`'s inline feature bootstrap depends on exactly that mode (`generateFeatureDocsPlaceholder`).
- `src/agents/bootstrap-agent.ts` (the tool-equipped scan agent) and the inline single-shot `bootstrapAgent` in `src/cli/bootstrap.ts` are deleted, along with the Mastra tool wrappers in `src/tools/codebase.ts` (`buildCodebaseTools`) that existed only to give that scan agent file-exploration tools.
- The `lv bootstrap` CLI keeps a small, non-LLM responsibility in support of the new skill: exposing the same inputs the old prompts used to assemble (repo root, `scan_extensions`/`scan_skip_dirs`, `output_language`, any existing draft docs, feature name/description hint), and performing the same post-generation bookkeeping the CLI flow used to bundle in (`docs/features/INDEX.md` update, optional Lark Features table sync) once the skill has written the two files itself. Exact shape (a JSON "instructions" subcommand vs. a "finalize" subcommand, or both) is a design decision, not fixed here.

## Capabilities

### New Capabilities
- `lv-bootstrap/skill-based-generation`: the `lv-bootstrap` skill (and, for known-shape agents, slash command) that explores the repo (or reads given paths) and writes `overview.md`/`design.md` directly in the calling agent's own turn, replacing the Mastra-agent-driven scan and `--paths` modes, with identical generation behavior across every coding agent it's installed for.
- `lv-init/lv-bootstrap-skill-install`: `lv init` installing and idempotently patching the `lv-bootstrap` skill (and command, for known-shape agents) into every coding agent it detects OpenSpec was installed for, mirroring how it already wires OpenSpec's own skill/command files today.

### Modified Capabilities
- `lv-bootstrap/output-language`: its requirements currently describe "bootstrap agents" (the Mastra scan and single-shot agents) honoring the repo's `output_language`; with those agents removed, the same guarantee has to be restated for the new skill's own instructions instead.
- `lv-bootstrap/lark-feature-table-sync`: its requirements currently name `lv bootstrap <feature-id>` (run directly) as one of two triggers for a Features-table sync; that trigger has to be restated for the new skill/command flow, since the CLI itself no longer generates docs in the two modes that used to trigger it.

## Impact

- Removed: `src/agents/bootstrap-agent.ts`; the inline `bootstrapAgent` and the two LLM-driven code paths it and the scan agent served (`runBootstrapFromScan`/`generateFeatureDocsFromScan`, `runBootstrapFromPaths`) in `src/cli/bootstrap.ts`; the Mastra tool wrappers (`buildCodebaseTools`) in `src/tools/codebase.ts` that existed only to serve those agents.
- Changed: `src/cli/init.ts` (new idempotent, glob-based install logic for the `lv-bootstrap` skill/command files, alongside the existing OpenSpec install/patch functions); `src/prompts.ts` (new skill/command instructional text, replacing `BOOTSTRAP_AGENT_INSTRUCTIONS`, `buildBootstrapScanPrompt`, `buildBootstrapOverviewPrompt`, and `buildBootstrapDesignPrompt`); `src/cli/bootstrap.ts` (keeps placeholder mode as-is, gains whatever thin CLI surface the new skill needs for config lookup, index update, and Lark sync).
- Unaffected: `lv bootstrap <feature-id> --new-feature` (placeholder mode, no LLM call); `lv start`'s inline feature bootstrap (already placeholder-only via `generateFeatureDocsPlaceholder`, never the scan agent); `lv start`'s own feature-matching/splitting Mastra agents (`featureMatchAgent`/`featureSplitAgent` in `src/cli/start.ts`), which are out of scope for this change.
- Documentation: `docs/features/lv-bootstrap/{overview.md,design.md}` and `docs/features/lv-init/{overview.md,design.md}` will need a refresh (via the new skill itself, once it exists) after this change lands, since both currently describe the Mastra-agent-based flow this change removes. CLAUDE.md's "Agents" section, which documents `createBootstrapScanAgent()` and the inline `bootstrapAgent`, will also need updating to describe: (1) that `lv-bootstrap` is installed dynamically for whatever coding agents OpenSpec was installed for, matching the OpenSpec-delegation philosophy CLAUDE.md already documents, and (2) the small, explicitly maintained "known command shapes" table (Claude Code, Cursor today) that decides which of those agents additionally get a slash command versus skill-only.
- Dependency: `@mastra/core`'s `Agent` machinery is still used elsewhere in `lv` (e.g. `lv start`'s feature-match/split agents) and is not removed as a dependency by this change — only the bootstrap-specific agents and their supporting tools go away.
